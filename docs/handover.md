## 7. 開発環境と進め方の注意

- このPCにはVisual C++とCMakeがない（導入には管理者権限が要る）。C++はPRのCIでビルドとテストを確かめる
- GitHub CLIは `& "$env:LOCALAPPDATA\Programs\gh\bin\gh.exe"`。PRを作った直後の `gh pr checks --watch` は「no checks reported」になることがあるので、もう一度実行する
- 並行して作業するときは、`git worktree add -b <ブランチ> ..\IME-<名前> origin/main` で作業場所を分ける（`C:\dev\IME` は別のセッションが使っていることがある）。CMakeListsのソースの並びは衝突しやすいので、マージの前に `origin/main` を取り込み、両方の行を残す
- CIのログは、PowerShellのリダイレクトでは日本語が化ける。`Start-Process gh -ArgumentList ... -RedirectStandardOutput <ファイル> -NoNewWindow -Wait` で保存して読む
- MSVCは `/W4 /WX` で、変数が別の変数を隠す警告（C4456）を失敗にする。macOS・Linuxでは警告が出ないので、送信の前に確かめる
- Linuxのclang（fuzzingジョブ）では、既定値を持つ入れ子の構造体を `std::optional::emplace` で作れない
- ファイルを丸ごと置き換えるときは `Copy-Item -Force x.new x; Remove-Item x.new` を使い、サイズを確かめてからコミットする（`Move-Item` では中身が空になったことがある）
- TIP: D2D・DWriteなどのCOMのオブジェクトを `DllMain` や静的なデストラクターで解放しない（テストの終了時に落ちた）。CIのランナーではキーボードのフォーカスが得られないことがあるため、TIPの動作のテストはテスト用の入口関数（`AstelioTipTestKey` など）から呼ぶ
- TIPの試用は `tools/Get-AstelioTip.ps1`（mainの最新コミットのCIを待って取得する）と、管理者のPowerShellで `tools/Register-AstelioTip.ps1`
